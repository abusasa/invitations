# ToiTech MVP — запуск

## 1. Supabase
1. Создай проект на supabase.com.
2. SQL Editor → вставь и выполни весь `schema.sql` целиком.
3. Database → Replication → включи репликацию для таблицы `invitations`
   (нужно для мгновенного исчезновения баннера после оплаты).
4. Authentication → Users → Add user → создай админ-аккаунт (email +
   пароль). Этот email пропиши в `config.js` как `ADMIN_EMAIL`.

## 2. config.js
Заполни `SUPABASE_URL`, `SUPABASE_ANON_KEY` (Project Settings → API) и
`ADMIN_EMAIL`.

## 3. Иконки
В `icons/` лежат временные плейсхолдеры (icon-192.png, icon-512.png) —
просто монограмма "T" на тёмном фоне. Замени на реальный логотип перед
продакшеном, размеры и назначение (favicon / home-screen) менять не
нужно.

## 4. Файлы
| Файл | Назначение |
|---|---|
| `schema.sql` | Таблицы, RLS, триггер, RPC-функция |
| `config.js` | Ключи и настройки, общие для всех страниц |
| `create.html` | Публичный визард создания приглашения |
| `index.html` | Публичная страница приглашения (то, что видит гость) |
| `admin.html` | PWA-панель администратора |
| `manifest.json` | PWA-манифест для admin.html |

## 5. Где я отступил от исходного ТЗ и почему

- **RLS + `get_invitation()` вместо прямого SELECT** — иначе anon-ключ
  в браузере позволял бы выгрузить всю таблицу `invitations` целиком
  (имена и WhatsApp-номера всех клиентов), а не только открытую страницу.
- **Supabase Auth вместо пароля в JS** — пароль, зашитый в код
  клиентской страницы, виден любому через "Просмотр кода страницы".
  На экране входа осталось только поле пароля — email админа скрыт
  в `config.js`, так что UX почти не изменился.
- **`event_date` заполняется через `datetime-local` и хранится как ISO
  8601 строка** — нужно для точного обратного отсчёта; поле в БД
  осталось `VARCHAR`, как в ТЗ.
- **Realtime-подписка** на UPDATE — реализует буквальное требование
  "баннер моментально исчезает" без перезагрузки страницы.

## 6. Известное ограничение (осознанно оставлено вне MVP)
Rate limiting на создание сайтов проверяется через `localStorage` —
это защита от случайного спама с одного браузера, а не от
целенаправленной атаки (localStorage легко очистить). Для полноценной
защиты понадобится серверная проверка (например, Supabase Edge
Function с ограничением по IP) — не стал добавлять, так как это уже
выходит за рамки MVP из ТЗ.
